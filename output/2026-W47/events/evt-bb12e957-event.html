事件摘要

核心突破：Inkitt 事件驱动编排器实现持久化状态与有限重试下的安全 PR 交付；Apex Agents 以 PageRank AST 压缩和 Git 原生检查点提升智能体架构感知与回滚能力；CodeRabbit 报告以 OpenAI 模型治理实现 20 倍交付量。 解决的问题：自主编码智能体在真实仓库中执行多文件变更时，缺乏统一的编排状态管理、权限隔离、错误恢复和人工审批机制，导致不可控合并、CI 失败循环和上下文膨胀。 研究价值：为编码智能体从代码生成走向受控交付提供了可复用的工程模式：事件驱动状态机、短期凭证隔离、幂等 Webhook 处理、AST 级上下文压缩和原子 Git 快照，可作为后续 agent harness 设计的参考基线。

Inkitt 构建了一个一次性拉取请求（PR）创建器，可以自动完成小型、低风险的软件变更，从接收任务一直执行到生成可供测试和审查的草稿 PR。该工作流可以通过 Slack、Linear，或者另一个智能体发起的 API 调用触发，并在远程基础设施上运行，从而减少开发者在本地配置和监督编码智能体的需要。Inkitt Tech 在一篇技术文章中表示，该系统已经每天用于交付代码。 Inkitt 首席工程师 Agi Letkiewicz Tanner 将其描述为： 一种事件驱动的编排器，它负责协调短生命周期的智能体容器，而不是依赖固定流水线。 各个阶段分别负责需求说明、实现、验证、CI 失败修复和合并冲突解决。编排器会将每次运行的状态持久化到数据库中，因此执行过程可以从已经记录的状态继续恢复。 Inkitt 一次性 PR 创建器架构（来源：Inkitt 博客文章） 该编排器将决策逻辑与副作用分离。其核心状态转换函数会根据当前运行状态和传入事件确定下一步操作，但不会直接访问数据库、网络或语言模型。编排器负责保管外部系统的凭证，智能体容器则只会获得短期有效的代码仓库 Token 和模型凭证。智能体无法直接访问 Slack 或 Linear 凭证、云身份，也不能随意建立网络连接。另有一项独立检查会查看实际的 Git Diff，确保变更没有触及受限制的路径。 Inkitt...

事件摘要

核心突破：识别智能体工作负载的三重基础设施挑战（突发计算、状态持久化、内存容量），提出 Cube Sandbox 双弹性 + IAA 存内压缩 + CXL 分层的协同方案，并量化 2GB/vCPU 内存缺口与 IAA 压缩延迟降低至 1/11。 解决的问题：智能体工作负载呈突发计算模式（想一下干一下），且跨 Action 需保留数据、依赖、执行状态，传统围绕模型推理设计的基础设施无法同时满足弹性算力、状态持久化和高密度内存需求。 研究价值：量化了智能体高密度部署的内存容量缺口（2GB/vCPU），展示 IAA 将压缩延迟从 5.70ms 降至 0.51ms、解压延迟从 0.96ms 降至 0.08ms，为智能体基础设施的硬件-软件协同设计提供了具体参考。

当前可得资料的证据边界（未说明不等于未开展）：方案绑定腾讯云与英特尔特定硬件平台，缺乏跨平台验证和独立基准测试；IAA 压缩比（2.1:1）与延迟数据基于单一测试配置；CXL 内存扩展路径尚未展示实际部署效果；未涉及多智能体协作或递归执行场景

A1当AI从“会想”走向“会干”——腾讯云与英特尔共筑Agentic AI执行新底座

过去，人们与大模型的交互是一条相对简单的链路：输入 Prompt，模型生成 Response。进入 Agent 时代，这条链路变成了“规划—推理—行动—反馈”的循环。一次用户请求，可能进一步调用网页、API、数据、工具、代码和其他系统，展开为成千上万个机器动作。 以“分析销售数据并生成报告”为例，Agent 需要读取文件、准备依赖、编写并运行代码、检查结果，再根据反馈修改重试。生成文字只是其中一步，任务要靠一连串实际操作才能完成。CPU 也因此不再只是为 GPU 做配套，而要参与整个工作流的编排和 Action 执行。 问题随之而来：当 AI 从“生成答案”走向“执行任务”，过去围绕模型推理设计的基础设施，还够用吗？腾讯云与英特尔围绕智能体基础设施的协同，正是从这条更长的执行链路出发，回应计算、内存与执行环境上的三重挑战。 第一重挑战：算力有起伏，现场不能丢 Agent 并不是始终满负荷计算。它更像“想一下，干一下，再想一下”：等待模型或工具返回时，CPU 需求回落；处理数据、执行代码、运行测试时，计算需求又迅速上升。这是 Agent 负载的常态——资源需求随任务推进起起伏伏，要求基础设施能够跟随行动节奏灵活调配算力，而不是始终按照峰值预留。 计算可以暂歇，工作现场却不能随之消失。已经载入的数据、装好的依赖、执行到一半的程序，以及多轮交互中累积的状态，都需要跨越多个...
